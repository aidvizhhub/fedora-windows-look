Сосед `26-ip-leak-map.md` — про клиента. Этот — про **сервер**: как отдавать сервис
(игру/веб/что угодно) наружу так, чтобы клиенты видели адрес **VPS**, а не твою квартиру.
Плюс — гигиена, из-за которой IP и личность палят вообще без техники.

## Почему не хостить из дома

- Публичные IPv4 **постоянно сканируются всем интернетом** (Shodan, Censys, masscan-боты)
  по диапазонам провайдера — «светить IP» не нужно, найдут сами. Открытые порты
  индексируются.
- За IP стоит **провайдер → абонент → имя/адрес/платёжка**. Abuse-контакт по IP выдаётся
  публично (RIPE/ARIN/APNIC), а по инциденту ISP отдаёт данные по запросу.
- РФ: **374-ФЗ (Яровая, 2016)** — метаданные до 6 мес.; **СОРМ** обязывает операторов
  хранить и выдавать по запросу. Динамический IP **не спасает** — провайдер хранит лог
  «кто держал адрес когда».
- Игровой сервер из дома = игроки видят твой адрес; обиженный игрок **DDoS-ит твой
  домашний канал**, а не «сервер». Пассивные DNS-архивы хранят историю резолва — прятать
  надо **до** первого резолва.

**Вывод:** наружу — только машина, которую не жалко и которая не там, где ты живёшь.

## Схема: наружу только VPS, дом — за туннелем

```
   клиенты ──►  VPS (публичный IP)  ──WireGuard-туннель──►  домашняя машина (за NAT)
                     ▲                                              │
              Nginx/Caddy reverse proxy                    сервис слушает 127.0.0.1
```

- Домашняя машина **сама** поднимает WireGuard к VPS (`Endpoint = IP VPS`), сервис
  слушает `127.0.0.1`. Порты из дома **не пробрасываются**.
- VPS терминирует входящее и проксирует через туннель. Клиенты видят IP VPS.

Конфиг и грабли (проверяемые):

- **`PersistentKeepalive = 25`** на домашнем пире — держит NAT-маппинг живым.
- **`AllowedIPs`** — это и маршрут, и allow-list источников; для «наружу только VPS»
  хватает узких подсетей (полный `0.0.0.0/0` не обязателен).
- На VPS: **`net.ipv4.ip_forward=1`** + открыть только UDP-порт WireGuard.
- **`Endpoint` — только публичный IP/порт** (не `10.x`/`192.168.x`); частая ошибка —
  handshake не встаёт.
- Клиент WireGuard **не перечитывает** изменившийся DNS имени endpoint — при смене IP
  сервера нужен рестарт (или внешний агент).
- **Грабля (главная):** на VPS `sudo wg show` покажет `endpoint` домашнего пира —
  **твой реальный домашний IP:порт**. Для «своего» VPS это норма, но **оператор VPS
  тебя видит**; компрометируют/изымут VPS — получат и твой адрес. Хочешь прятаться и от
  оператора — цепочка (промежуточный VPN/Tor) либо VPS не на свои данные.

**Вердикт схемы:** 🥇 лучший баланс «просто/надёжно» для веба и игр; прячет от клиентов,
**не** от оператора VPS.

## Cloudflare Tunnel (`cloudflared`): сервис без белого IP и без открытых портов

`cloudflared` открывает **только исходящее** шифрованное соединение к Cloudflare —
входящие порты на твоей стороне не нужны вообще; работает даже за CGNAT.

- Проксирует из коробки **только HTTP/HTTPS/WebSocket**. Произвольный TCP/UDP (игровой) —
  либо клиент `cloudflared access tcp`, либо **Spectrum**: Pro/Business — выбранные
  приложения (Minecraft/SSH/RDP), любые TCP/UDP — **только Enterprise**.
- Egress-порты: TCP 443 к api Cloudflare + UDP **7844** к `region1/2.v2.argotunnel.com`
  (QUIC предпочтительно). Если 7844 режут — пробуй HTTP/2-фолбэк.
- Приложение биндить на **`127.0.0.1`** (не `0.0.0.0`, не `localhost` — на Ubuntu это
  `::1` → 502). В docker — `"127.0.0.1:8080:80"`.
- Туннель **не закрывает порты сам**: убери allow 80/443 из firewall и, главное, **снеси
  старую A-запись** — иначе DNS продолжает публиковать origin IP.
- Минусы: Cloudflare **терминирует TLS** (видит plaintext, не отключить), а аккаунт CF =
  email/карта = запись личности.
- **РФ [факт, 09.06.2025]:** локальные ISP режут сайты/туннели за Cloudflare до **16 КБ**,
  могут блочить порт 7844. Для пользователей из РФ входная точка ненадёжна.

**Вердикт:** 🥈 для веб-сервиса + «бесплатно» TLS/DDoS. Для игрового TCP/UDP — не он
(или Spectrum/Enterprise).

## Входящий порт через VPN: Mullvad больше **не умеет**

- **[факт] Mullvad убил port forwarding:** с 29.05.2023 нельзя добавить/сменить порты,
  существующие удалены 01.07.2023 (abuse, blacklist, звонки от правоохранителей).
  Ни настройки аккаунта, ни WireGuard-трюк порт не вернут.
- Нужен входящий порт (сидбокс, P2P-сервис) — VPN с port-forward: **Proton VPN**
  (NAT-PMP, до 5 портов), **AirVPN**, **PIA**, **PureVPN**. Даёт входящие на exit-IP VPN,
  домашний адрес не светит. Минус — доверие переезжает к этому VPN; для латентного
  гейминга обычно не годится (нужен ровно один порт/протокол).

## Tor onion — сервис без IP вообще

Onion-сервис (v3, `.onion`, 56 символов) принимает соединения только через Tor; сканировать
Tor-сеть как интернет нельзя, IP не показывается **никому**. Настройка: `HiddenServiceDir`
+ `HiddenServicePort <pub> 127.0.0.1:<local>` → адрес в файле `hostname`.

Цена: медленно (релеи по миру, сотни мс), клиенту нужен Tor. ISP видит, что ты
**пользуешься Tor** (не что именно). Вердикт: 🥉 веб/API/админка — да; игры/стрим — нет.

## Гигиена «палева» (техника тут ни при чём)

Сеть — половина. Вторая половина — **ты**. Чек-лист:

| Канал | Что светит | Как прикрыть |
|---|---|---|
| Ник/аватар/подпись | один и тот же между площадками | уникальный ник на проект, поиск по нику бьёт (Sherlock 400+/Maigret 4100+), аватар — reverse image search |
| `git`-коммиты | `user.email` вшит в коммит и публикуется с пушем | `noreply@users.noreply.github.com`, `includeIf` по папкам, «Block command line pushes that expose my email»; старые — `git filter-repo` (хэши сменить) |
| Заголовки почты | `Received:` цепочка / `X-Originating-IP` с твоим IP | webmail/релей вместо десктоп-клиента и своего MTA; проверка «Show original» |
| WHOIS домена | регистрационные данные | gTLD после GDPR по умолчанию **redacted** (имя/адрес/тел/email), но регистратор **хранит** и отдаёт по запросу; Njalla-style — регистрант = сам сервис |
| Платежи / KYC | карта/KYC связывает железо с тобой | no-KYC VPS + крипта (XMR); обычные облака хотят карту/ID |
| Аналитика/внешние скрипты | линкуют сервер с другими твоими свойствами | не ставить внешние шрифты/аналитику, или изолировать |
| Тайминги/часовой пояс | UTC+3 в постах/активности = регион | не светить локальное время/расписания |
| Админка с дома | один прямой коннект в логе хоста/ISP связывает тебя | заходить в панель **только** через VPN/туннель |
| Переиспользование ключей | тот же SSH/пароль/почта в личном и «теневом» | отдельные ключи/личности |

**Топ-10 одним взглядом:** ник/аватар; git-email; почта с origin-IP; WHOIS; платеж; повтор
ключей/логинов; админка с домашнего IP; часовой пояс/тайминги; аналитика; стилометрия и
поддержка с личного аккаунта.

## Verify — только факты

```bash
whois <внешний-IP-VPS> | grep -iE 'netname|country|org'   # что видно по сервису
curl -s https://am.i.mullvad.net/json | jq .ip             # с дома — адрес выхода
sudo wg show                                               # на VPS виден endpoint дома (это ожидаемо)
ss -lntup                                                  # на VPS — только WG + 80/443; БД закрыта
```

Снаружи клиент видит **IP VPS**. На VPS БД/внутренние порты — закрыты. WHOIS домена —
скрыт или сервисный.

## Откат

Остановить сервис и туннель (`systemctl stop ...` / убрать юнит), снять DNS-записи,
закрыть порты на VPS. Домашние настройки и роутер **не трогались**.
